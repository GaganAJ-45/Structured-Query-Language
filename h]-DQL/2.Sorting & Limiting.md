# 2. Sorting & Limiting

> Part of the **DQL** series. Runs against the `department` and `employee` tables — see [00-dataset.md](00-dataset.md) if you haven't set those up yet.

---

## 0. A Quick Word Before We Start

`WHERE` decides **which rows** should remain.

This file focuses on two different questions:

1. **`ORDER BY`** → In what order should the rows appear?
2. **`LIMIT` / `OFFSET`** → How many rows should I return, and where should I start?

The most useful flow to remember is:

```text
FROM
  ↓
WHERE
  ↓
SELECT
  ↓
ORDER BY
  ↓
LIMIT / OFFSET
  ↓
FINAL RESULT
```

For `ORDER BY + LIMIT/OFFSET`, use this mental model:

```text
FILTER → SORT → SKIP → TAKE
```

---

# 1. ORDER BY — Sorting Rows

By default, SQL does **not guarantee** any particular row order. If you need a predictable order, use `ORDER BY`.

## 1.1 Basic Syntax

```sql
SELECT first_name, salary
FROM employee
ORDER BY salary;
```

If no direction is specified, MySQL sorts in **ascending (`ASC`)** order by default.

---

## 1.2 ASC and DESC

| Keyword | Meaning |
|---|---|
| `ASC` | Ascending — low to high, A to Z, oldest to newest |
| `DESC` | Descending — high to low, Z to A, newest to oldest |

### Ascending

```sql
SELECT first_name, salary
FROM employee
ORDER BY salary ASC;
```

Example:

```text
30000
45000
60000
90000
120000
```

### Descending

```sql
SELECT first_name, salary
FROM employee
ORDER BY salary DESC;
```

Example:

```text
120000
90000
60000
45000
30000
```

---

## 1.3 Sorting by Multiple Columns

You can sort using more than one column.

```sql
SELECT dept_id, first_name, salary
FROM employee
ORDER BY dept_id ASC, salary DESC;
```

Read it as:

> First sort by `dept_id`. If multiple employees have the same department, sort those employees by `salary` from high to low.

Example:

```text
dept 1
    Employee A   120000
    Employee B    90000
    Employee C    70000

dept 2
    Employee D   150000
    Employee E    80000
```

### Important idea

The second sorting column matters **only when the first sorting column has a tie**.

---

## 1.4 Sorting by a Column Not in SELECT

You can sort using a column without displaying it.

```sql
SELECT first_name, designation
FROM employee
ORDER BY hire_date DESC;
```

The result displays only:

```text
first_name
designation
```

but MySQL still uses `hire_date` to decide the order.

---

## 1.5 Sorting by Column Position

You can sort using the position of the selected column:

```sql
SELECT first_name, salary
FROM employee
ORDER BY 2 DESC;
```

Here:

```text
1 → first_name
2 → salary
```

So `ORDER BY 2 DESC` means:

> Sort by `salary DESC`.

This works in MySQL, but using the actual column name is clearer:

```sql
ORDER BY salary DESC;
```

# 2. The Most Important Flow: WHERE → ORDER BY → LIMIT

Do not think of the query as one large instruction.

Break it into stages.

Suppose we write:

```sql
SELECT first_name, salary
FROM employee
WHERE salary IS NOT NULL
ORDER BY salary DESC
LIMIT 5;
```

## Step 1 — FROM

```sql
FROM employee
```

Start with the employee table.

```text
employee table
     ↓
all employee rows
```

---

## Step 2 — WHERE

```sql
WHERE salary IS NOT NULL
```

Remove employees whose salary is `NULL`.

```text
100 employee rows
        ↓
salary IS NOT NULL
        ↓
remaining rows
```

### Meaning

`WHERE` answers:

> **Which rows do I want?**

---

## Step 3 — SELECT

```sql
SELECT first_name, salary
```

Choose the columns you want to display.

```text
first_name
salary
```

### Meaning

`SELECT` answers:

> **Which columns do I want to see?**

---

## Step 4 — ORDER BY

```sql
ORDER BY salary DESC
```

Sort the remaining rows from the highest salary to the lowest.

```text
150000
145000
140000
130000
125000
120000
...
```

### Meaning

`ORDER BY` answers:

> **In what order should I see them?**

---

## Step 5 — LIMIT

```sql
LIMIT 5
```

Take only the first 5 rows after sorting.

```text
150000
145000
140000
130000
125000
```

### Meaning

`LIMIT` answers:

> **How many rows should I return?**

---

## The complete mental flow

```text
FROM employee
     ↓
WHERE salary IS NOT NULL
     ↓
SELECT first_name, salary
     ↓
ORDER BY salary DESC
     ↓
LIMIT 5
     ↓
FINAL RESULT
```

Or simply:

```text
FILTER → SORT → TAKE
```

---

# 3. LIMIT — Restricting Row Count

`LIMIT` controls how many rows are returned.

## 3.1 Basic Syntax

```sql
SELECT *
FROM employee
LIMIT 5;
```

This returns 5 rows.

### Important

Without `ORDER BY`, these are **just 5 rows**, not necessarily:

- the highest-paid 5
- the lowest-paid 5
- the newest 5
- the oldest 5

For example:

```sql
SELECT *
FROM employee
LIMIT 5;
```

means:

> Give me 5 rows.

But:

```sql
SELECT *
FROM employee
ORDER BY salary DESC
LIMIT 5;
```

means:

> Give me the 5 highest-paid employees.

That difference is important.

---

# 4. OFFSET — Skipping Rows

`OFFSET` tells MySQL how many rows to skip **after the result has been ordered**.

Example:

```sql
SELECT first_name, salary
FROM employee
ORDER BY emp_id
LIMIT 10 OFFSET 20;
```

Think about the rows after sorting:

```text
Row 1
Row 2
Row 3
...
Row 20
Row 21
Row 22
Row 23
...
Row 30
```

`OFFSET 20`:

```text
Skip rows 1–20
```

Then `LIMIT 10`:

```text
Take rows 21–30
```

So:

```text
OFFSET 20
     ↓
skip 20
     ↓
LIMIT 10
     ↓
take 10
```

### Golden rule

```text
SORT → SKIP → TAKE
```

---

# 5. LIMIT + OFFSET

Basic syntax:

```sql
SELECT *
FROM employee
ORDER BY emp_id
LIMIT 10 OFFSET 20;
```

Meaning:

> Sort by `emp_id`, skip the first 20 rows, then return the next 10 rows.

Result:

```text
Rows 21–30
```

---

# 6. MySQL LIMIT Comma Syntax

MySQL also supports:

```sql
LIMIT offset, count
```

So this:

```sql
LIMIT 20, 10;
```

means:

```text
OFFSET = 20
LIMIT  = 10
```

It is equivalent to:

```sql
LIMIT 10 OFFSET 20;
```

### Very important

In comma syntax:

```text
LIMIT offset, count
       ↑       ↑
      skip    take
```

Example:

```sql
SELECT first_name, salary
FROM employee
ORDER BY emp_id
LIMIT 20, 10;
```

means:

> Skip 20 rows and take 10 rows.

---

# 7. Pagination

Pagination means showing results page by page.

Suppose:

```text
page size = 10 employees
```

## Page 1

```sql
SELECT *
FROM employee
ORDER BY emp_id
LIMIT 10 OFFSET 0;
```

```text
Skip 0
Take 10

→ rows 1–10
```

---

## Page 2

```sql
SELECT *
FROM employee
ORDER BY emp_id
LIMIT 10 OFFSET 10;
```

```text
Skip 10
Take 10

→ rows 11–20
```

---

## Page 3

```sql
SELECT *
FROM employee
ORDER BY emp_id
LIMIT 10 OFFSET 20;
```

```text
Skip 20
Take 10

→ rows 21–30
```

---

## General Formula

```text
OFFSET = (page_number - 1) × page_size
```

Example:

```text
Page 4
Page size = 10

OFFSET = (4 - 1) × 10
       = 30
```

So:

```sql
LIMIT 10 OFFSET 30;
```

returns:

```text
rows 31–40
```

---

# 8. ORDER BY + LIMIT — Top / Bottom Results

This is one of the most common SQL patterns.

## Top 5 highest-paid employees

```sql
SELECT first_name, salary
FROM employee
ORDER BY salary DESC
LIMIT 5;
```

Flow:

```text
All employees
     ↓
Sort salary high → low
     ↓
Take first 5
     ↓
Top 5 highest-paid employees
```

---

## Bottom 5 lowest-paid employees

```sql
SELECT first_name, salary
FROM employee
ORDER BY salary ASC
LIMIT 5;
```

Flow:

```text
All employees
     ↓
Sort salary low → high
     ↓
Take first 5
     ↓
Bottom 5 lowest-paid employees
```

---

# 9. WHERE + ORDER BY + LIMIT

Now combine filtering, sorting, and limiting.

### Example

> Find the top 5 highest-paid employees hired after 2020.

```sql
SELECT first_name, last_name, salary, hire_date, dept_id
FROM employee
WHERE hire_date > '2020-01-01'
  AND salary IS NOT NULL
ORDER BY salary DESC
LIMIT 5;
```

### Think through the flow

```text
employee table
     ↓
WHERE
     ↓
keep employees hired after 2020
     ↓
remove NULL salaries
     ↓
ORDER BY salary DESC
     ↓
highest salary first
     ↓
LIMIT 5
     ↓
take top 5
```

### Important correction

This query finds:

> **Top 5 highest-paid employees hired after 2020.**

It does **NOT** mean:

> Top 5 highest-paid employees, one per department.

Those are different questions.

For "one per department", you will need a different technique such as a window function.

# 10. Aliases and ORDER BY

You can create an alias in `SELECT` and use that alias in `ORDER BY`.

```sql
SELECT
    first_name,
    salary * 12 AS annual_salary
FROM employee
ORDER BY annual_salary DESC;
```

Here:

```text
salary × 12
     ↓
annual_salary
     ↓
ORDER BY annual_salary DESC
```

This works because `ORDER BY` can use a `SELECT` alias in MySQL.

For example:

```sql
SELECT first_name, salary * 12 AS annual_salary
FROM employee
ORDER BY annual_salary DESC
LIMIT 5;
```

This gives the 5 employees with the highest annual salary.

> This same alias privilege is explained in more depth — including *why* `HAVING` doesn't get the same privilege — in [4-group-by-and-having.md](4-group-by-and-having.md).

# 11. Important Concept: Syntax Order vs Logical Processing Order

This is where many beginners get confused.

## The order you WRITE a query

```text
SELECT
FROM
WHERE
ORDER BY
LIMIT
OFFSET
```

Example:

```sql
SELECT first_name, salary
FROM employee
WHERE salary IS NOT NULL
ORDER BY salary DESC
LIMIT 5 OFFSET 10;
```

---

## The logical flow to UNDERSTAND the query

For the topics in this file, use:

```text
FROM
  ↓
WHERE
  ↓
SELECT
  ↓
ORDER BY
  ↓
LIMIT / OFFSET
  ↓
FINAL RESULT
```

And for the final three operations:

```text
FILTER → SORT → SKIP → TAKE
```

### Important nuance

This is a **learning model**, not a claim about every internal implementation detail of MySQL.

You should also remember that `LIMIT` and `OFFSET` are normally treated together as the final row restriction:

> **After sorting, skip the requested number of rows and return the requested number of rows.**

### The full picture (once GROUP BY/HAVING enter the mix)

Once you reach [4-group-by-and-having.md](4-group-by-and-having.md), the complete logical order actually looks like this:

```text
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT/OFFSET
```

The `FROM → WHERE → SELECT → ORDER BY → LIMIT/OFFSET` flow used throughout this file is simply that same order with the grouping steps removed, since this file doesn't use `GROUP BY` or `HAVING` yet.

# 12. What Each Clause Is Asking

When solving a SQL problem, ask these questions:

| Question | Clause |
|---|---|
| Where is my data coming from? | `FROM` |
| Which rows do I want? | `WHERE` |
| Which columns do I want to display? | `SELECT` |
| How should the rows be arranged? | `ORDER BY` |
| How many rows should I skip? | `OFFSET` |
| How many rows should I take? | `LIMIT` |

This is easier than trying to memorize a large execution-order diagram.

# 13. Common Mistakes

## Mistake 1 — LIMIT without ORDER BY

```sql
SELECT *
FROM employee
LIMIT 5;
```

This means:

> Return 5 rows.

It does **not** mean:

> Return the top 5 employees.

For top 5, use:

```sql
ORDER BY some_column DESC
LIMIT 5;
```

---

## Mistake 2 — Mixing up LIMIT and OFFSET

```sql
LIMIT 20, 10;
```

means:

```text
20 = offset
10 = number of rows
```

NOT:

```text
20 = number of rows
10 = offset
```

---

## Mistake 3 — Expecting ORDER BY to create groups

```sql
ORDER BY dept_id;
```

does **not** create SQL groups.

It only sorts the rows by department ID.

Compare:

```sql
ORDER BY dept_id;
```

→ sorts rows

```sql
GROUP BY dept_id;
```

→ creates groups for aggregation

You will study `GROUP BY` in the next section.

---

## Mistake 4 — Assuming "one per department"

This:

```sql
SELECT first_name, dept_id
FROM employee
ORDER BY salary DESC
LIMIT 5;
```

can return multiple employees from the same department.

It means:

> Top 5 employees overall.

It does not mean:

> One employee from each department.

# 15. Quick Recap

| Keyword | What it does |
|---|---|
| `ORDER BY` | Sorts rows |
| `ASC` | Low → high / A → Z |
| `DESC` | High → low / Z → A |
| `LIMIT n` | Takes at most `n` rows |
| `OFFSET n` | Skips the first `n` rows |
| `LIMIT n OFFSET m` | Skip `m`, then take `n` |
| `LIMIT m, n` | MySQL shorthand: skip `m`, take `n` |

## The Golden Rule

Remember:

```text
FROM
 ↓
WHERE
 ↓
SELECT
 ↓
ORDER BY
 ↓
LIMIT / OFFSET
 ↓
RESULT
```

And for sorting/limiting:

```text
FILTER → SORT → SKIP → TAKE
```
