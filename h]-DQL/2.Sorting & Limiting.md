## 0. A Quick Word Before We Start

`WHERE` decided *which* rows show up. This file decides **the order** they show up in, and **how many** of them you actually want to see. Because nobody scrolling through 100 employees wants them in random database order — that's like a library that shelves books by "whenever it felt like it."

---

## 1. ORDER BY — Sorting Rows

By default, SQL doesn't guarantee any particular row order — what you get back is whatever order the engine feels like giving you (usually insertion order, but never rely on that). `ORDER BY` forces a specific, predictable order.

### 1.1 Basic syntax
```sql
SELECT first_name, salary FROM employee ORDER BY salary;
```
> With no direction specified, `ORDER BY` sorts **ascending (`ASC`)** by default — smallest/earliest first.

### 1.2 ASC and DESC

| Keyword | Meaning |
|---|---|
| `ASC` | Ascending — low to high, A to Z, oldest to newest *(default, can be omitted)* |
| `DESC` | Descending — high to low, Z to A, newest to oldest |

```sql
-- Highest paid employees first
SELECT first_name, salary FROM employee ORDER BY salary DESC;

-- Same thing, but explicit about ascending
SELECT first_name, salary FROM employee ORDER BY salary ASC;
```

### 1.3 Sorting by multiple columns

You can sort by more than one column — the second column only matters when there's a **tie** in the first.

```sql
SELECT dept_id, first_name, salary
FROM employee
ORDER BY dept_id ASC, salary DESC;
```
> Reads as: *"Group by department first (low to high), and within each department, show the highest earners first."* Think of it like sorting a class list by section, then by roll number within each section.

### 1.4 Sorting by a column not in the SELECT list

```sql
SELECT first_name, designation FROM employee ORDER BY hire_date DESC;
```
> Totally legal — you can sort by `hire_date` even without displaying it. The output just won't *show* the column you sorted by, only its effect.

### 1.5 Sorting by column position (works, but avoid it)

```sql
SELECT first_name, salary FROM employee ORDER BY 2 DESC;  -- sorts by the 2nd selected column (salary)
```
> This works in MySQL, but it's fragile — reorder your `SELECT` columns later and your sort silently breaks. Use actual column names.

## 1.5 Execution Priority — ORDER BY, LIMIT & OFFSET

Before jumping into `LIMIT`, it's worth being clear on **the order MySQL actually processes these clauses in** — not the order you type them.

```
1. WHERE   →   2. ORDER BY   →   3. LIMIT   →   4. OFFSET
```

`ORDER BY` **always** runs before `LIMIT`/`OFFSET` — this isn't optional, it's how the SQL engine is built.

### Why this matters — walked through

```sql
SELECT first_name, salary
FROM employee
ORDER BY salary DESC
LIMIT 5;
```

What actually happens internally:
1. All matching rows are gathered.
2. **Every row gets sorted first** — the *entire* result set, by `salary DESC`.
3. **Only then** does `LIMIT 5` chop off everything except the top 5 rows of that already-sorted list.

If it worked the other way around — `LIMIT` first, *then* sort — you'd get 5 random rows and sort just those, which is not what "top 5 highest paid" means at all.

### LIMIT and OFFSET — read as two sequential steps

```sql
SELECT * FROM employee
ORDER BY emp_id
LIMIT 10 OFFSET 20;
```

1. **`OFFSET 20`** conceptually happens first — skip the first 20 rows of the already-sorted list.
2. **`LIMIT 10`** then grabs the next 10 rows from wherever the offset left off.

Even though `LIMIT` is written *before* `OFFSET` in the syntax, the *skip* logically has to happen before the *take* — you can't take 10 rows until you know where to start taking from.

> **One-line rule:** Sort everything first (`ORDER BY`), then skip some (`OFFSET`), then take a fixed number (`LIMIT`) — always in that logical order, regardless of how you arrange the keywords in your query.

## 2. LIMIT — Restricting Row Count

`LIMIT` caps how many rows come back, regardless of how many actually matched.

```sql
-- Just the top 5 rows (in whatever order the query returns them)
SELECT * FROM employee LIMIT 5;
```

### 2.1 LIMIT is almost always paired with ORDER BY

```sql
-- Top 5 highest-paid employees
SELECT first_name, salary FROM employee ORDER BY salary DESC LIMIT 5;
```
> Without `ORDER BY`, `LIMIT 5` just grabs *some* 5 rows — not necessarily the top anything. `LIMIT` alone answers "give me a handful," `ORDER BY` + `LIMIT` together answers "give me the *best/worst* handful." Big difference for a report that's supposed to show your top performers.

---

## 3. OFFSET — Skipping Rows (Pagination)

`OFFSET` skips a number of rows before starting to return results — this is exactly how "Page 2" of search results, or an infinite-scroll feed, works under the hood.

### 3.1 Basic syntax
```sql
SELECT first_name, salary
FROM employee
ORDER BY emp_id
LIMIT 10 OFFSET 20;
```
> Skips the first 20 rows, then returns the next 10 — i.e., rows 21 to 30.

### 3.2 MySQL shorthand (comma syntax)
```sql
-- Same result as above, different syntax: LIMIT offset, count
SELECT first_name, salary FROM employee ORDER BY emp_id LIMIT 20, 10;
```
> ⚠️ Easy to mix up: in the comma form, the **first** number is the offset (rows to skip), the **second** is the row count. Many learners misread it the other way around at least once — you're not alone.

### 3.3 Pagination pattern (page-by-page)

If you're showing 10 employees per page:

```sql
-- Page 1 (rows 1–10)
SELECT * FROM employee ORDER BY emp_id LIMIT 10 OFFSET 0;

-- Page 2 (rows 11–20)
SELECT * FROM employee ORDER BY emp_id LIMIT 10 OFFSET 10;

-- Page 3 (rows 21–30)
SELECT * FROM employee ORDER BY emp_id LIMIT 10 OFFSET 20;
```

**General formula:**
```
OFFSET = (page_number - 1) × page_size
```

> This is literally how apps like Instagram or an e-commerce product listing decide what to load when you scroll or click "Next Page" — just `ORDER BY` + `LIMIT` + `OFFSET` wearing a nicer UI on top.

## 4. Putting It All Together

```sql
-- Top 5 highest-paid employees hired after 2020, one per department shown clearly
SELECT first_name, last_name, salary, hire_date, dept_id
FROM employee
WHERE hire_date > '2020-01-01' AND salary IS NOT NULL
ORDER BY salary DESC
LIMIT 5;
```

```sql
-- Page 3 of a "browse all departments alphabetically" screen, 5 per page
SELECT dept_name, location, manager_name
FROM department
ORDER BY dept_name ASC
LIMIT 5 OFFSET 10;
```

## 5. Quick Recap

| Keyword | What it does |
|---|---|
| `ORDER BY` | Sorts the result rows by one or more columns |
| `ASC` | Ascending order (default) |
| `DESC` | Descending order |
| `LIMIT n` | Returns only the first `n` rows |
| `OFFSET n` | Skips the first `n` rows before returning results |
| `LIMIT n OFFSET m` | Skip `m`, then take `n` — the pagination combo |
| Golden rule | `LIMIT` without `ORDER BY` gives you *a* set of rows, not *the* set you probably meant |
