# 1. Basic SELECT & Filtering Rows

> Part of the **DQL** series. Runs against the `department` and `employee` tables — see [00-dataset.md](00-dataset.md) if you haven't set those up yet (do it first, or every example here is just words on a screen).

## 0. A Quick Word Before We Start

`SELECT` is the command you will type roughly **9,000 times more often** than any other SQL keyword. It doesn't change a single row, doesn't break anything, doesn't need a `WHERE` clause to save your job — it just *looks*. Which makes it the safest place in all of SQL to be reckless and experiment.

So open your MySQL client, load the dataset, and let's go.

---

## 1. SELECT — Getting Data Out of a Table

### 1.1 Select everything
```sql
SELECT * FROM employee;
```
> `*` means "every column." Handy for exploring a table you don't know yet, but in real applications, avoid `SELECT *` — pulling 10 columns when you only need 2 is like ordering the entire menu because you were hungry for one samosa.

### 1.2 Select specific columns
```sql
SELECT first_name, last_name, salary FROM employee;
```

**Sample output (first 5 rows):**

| first_name | last_name | salary |
|---|---|---|
| Kabir | Iyer | 92450.00 |
| Aditya | Sharma | 61200.00 |
| Nisha | Reddy | NULL |
| Meena | Nair | 48750.00 |
| Om | Verma | 105300.00 |

*(exact values depend on your run of the dataset script — the pattern is what matters)*

## 2. Column Aliasing — Renaming Output Columns with `AS`

Sometimes a column name in the table is fine for storage, but ugly to show a human. `AS` renames it **just in the output** — the actual table is untouched.

```sql
SELECT first_name AS "First Name", salary AS "Monthly Salary"
FROM employee;
```

> `AS` is optional syntax-wise — `salary "Monthly Salary"` works too — but always write it. Future-you, reading this at 1 AM before a viva, will thank present-you.

---

## 3. DISTINCT — Removing Duplicate Values

Returns only **unique** values from a column, dropping repeats.

```sql
SELECT DISTINCT dept_id FROM employee;
```

If 100 employees are spread across 25 departments, this returns **at most 25 rows** — one per department that actually has an employee, not 100.

```sql
-- Works on multiple columns too — uniqueness is checked across the combination
SELECT DISTINCT dept_id, designation FROM employee;
```

> Without `DISTINCT`, you'd see `dept_id = 1` repeated as many times as there are employees in department 1. With it, department 1 shows up exactly once — SQL's version of "yes, I heard you the first time."

## 4. WHERE — Filtering Rows

`SELECT` decides *which columns*. `WHERE` decides *which rows*. Together they're basically SQL's "give me exactly this, and nothing else" combo.

```sql
SELECT first_name, salary FROM employee WHERE salary > 50000;
```

### 4.1 Comparison operators

| Operator | Meaning | Example |
|---|---|---|
| `=` | Equal to | `WHERE dept_id = 1` |
| `!=` or `<>` | Not equal to | `WHERE dept_id != 1` |
| `>` | Greater than | `WHERE salary > 50000` |
| `<` | Less than | `WHERE age < 25` |
| `>=` | Greater than or equal to | `WHERE age >= 30` |
| `<=` | Less than or equal to | `WHERE age <= 40` |

### 4.2 Logical operators — combining conditions

```sql
-- AND — both conditions must be true
SELECT * FROM employee WHERE dept_id = 1 AND salary > 60000;

-- OR — at least one condition must be true
SELECT * FROM employee WHERE dept_id = 1 OR dept_id = 2;

-- NOT — reverses a condition
SELECT * FROM employee WHERE NOT dept_id = 1;
```

> `AND` is the strict friend who wants both conditions satisfied. `OR` is the chill friend who's happy if even one shows up. `NOT` is the friend who just disagrees with whatever you said.

### 4.3 BETWEEN — Range filtering

```sql
SELECT first_name, age FROM employee WHERE age BETWEEN 25 AND 35;
```
> `BETWEEN` is **inclusive** on both ends — 25 and 35 themselves are included, not just the ages in between.

### 4.4 IN — Matching against a list

```sql
SELECT * FROM department WHERE location IN ('Bengaluru', 'Mumbai', 'Pune');
```
> This is just a cleaner way of writing `location = 'Bengaluru' OR location = 'Mumbai' OR location = 'Pune'` without repeating yourself three times like a nervous presenter.

### 4.5 LIKE — Pattern matching with wildcards

| Wildcard | Meaning |
|---|---|
| `%` | Matches **any number** of characters (including zero) |
| `_` | Matches **exactly one** character |

```sql
-- Names starting with 'A'
SELECT first_name FROM employee WHERE first_name LIKE 'A%';

-- Names ending with 'a'
SELECT first_name FROM employee WHERE first_name LIKE '%a';

-- Names that are exactly 4 characters long
SELECT first_name FROM employee WHERE first_name LIKE '____';

-- Emails containing 'sharma'
SELECT email FROM employee WHERE email LIKE '%sharma%';
```

### 4.6 IS NULL / IS NOT NULL

Remember those 4 employees in the dataset with a missing `salary`? This is exactly why they're there.

```sql
-- Find employees whose salary hasn't been entered yet
SELECT first_name, last_name FROM employee WHERE salary IS NULL;

-- Find employees who DO have a salary on record
SELECT first_name, last_name FROM employee WHERE salary IS NOT NULL;
```

> ⚠️ **Common trap:** `WHERE salary = NULL` looks logical but **never works** — in SQL, `NULL` means "unknown," and an unknown value can't be compared with `=` to anything, not even another `NULL`. You must use `IS NULL` / `IS NOT NULL`. This single mistake has cost more debugging hours across the world than almost any other SQL typo.

## 5. Putting It All Together — A Realistic Query

```sql
SELECT first_name, last_name, designation, salary
FROM employee
WHERE dept_id IN (1, 2, 3)
  AND salary IS NOT NULL
  AND salary BETWEEN 40000 AND 100000
  AND designation LIKE '%Developer%'
ORDER BY salary DESC;
```

Read left to right, this says: *"Give me developers in departments 1, 2, or 3, who actually have a salary on file, earning between ₹40,000–₹100,000, sorted highest paid first."* (We haven't covered `ORDER BY` in depth yet — that's next file — but it's a natural finisher for a filtered query like this.)

---

## 6. Quick Recap

| Keyword | What it does |
|---|---|
| `SELECT` | Chooses which **columns** to return |
| `*` | Shortcut for "all columns" — fine for exploring, avoid in real apps |
| `AS` | Renames a column in the output only |
| `DISTINCT` | Removes duplicate rows/values |
| `WHERE` | Filters which **rows** are returned |
| `AND` / `OR` / `NOT` | Combine or reverse conditions |
| `BETWEEN` | Range filter, inclusive on both ends |
| `IN` | Matches against a list of values |
| `LIKE` + `%` `_` | Pattern matching on text |
| `IS NULL` / `IS NOT NULL` | The **only** correct way to check for missing values |
