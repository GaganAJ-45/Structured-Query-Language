## Section A — Easy ☕ (Questions)

**A1.** List every employee's `first_name` along with their department's `dept_name`.

**A2.** List every employee's `first_name`, `designation`, and the `location` of their department.

**A3.** List every department's `dept_name`, even if it currently has **zero employees**.

**A4.** List every employee, and their department name if they have one — but also include employees whose `dept_id` doesn't match any real department (show `NULL` for the department in that case).

**A5.** Count how many employees exist in each department, showing the `dept_name` (not just the raw `dept_id`).

## Section C — Hard ☕☕☕ (Interview-style Questions)

**C1.** Write the exact same query in **two different ways** — once using a `JOIN`, and once using a subquery — to find all employees who work in a department based in `'Mumbai'`. *(Tests whether you understand that these two tools can solve the same problem.)*

**C2.** Rewrite a `RIGHT JOIN` between `employee` and `department` (on `dept_id`) as an equivalent `LEFT JOIN`, without changing what the query returns.

**C3.** Find the `dept_name` of the department with the **highest average salary**, using a `JOIN`. *(Hint: you'll need `GROUP BY`, `ORDER BY`, and `LIMIT` — three files' worth of concepts, all in one query.)*

**C5.** Explain, in one sentence, why this query is dangerous, and rewrite it correctly:
```sql
SELECT e.first_name, d.dept_name
FROM employee e, department d;
```

## Solutions — Section A (Easy)

**A1.**
```sql
SELECT e.first_name, d.dept_name
FROM employee e
JOIN department d ON e.dept_id = d.dept_id;
```
> Plain `JOIN` defaults to an `INNER JOIN` in MySQL — matches only.

**A2.**
```sql
SELECT e.first_name, e.designation, d.location
FROM employee e
JOIN department d ON e.dept_id = d.dept_id;
```

**A3.**
```sql
SELECT d.dept_name
FROM department d
LEFT JOIN employee e ON d.dept_id = e.dept_id;
```
> `department` needs to be on the **left** side (or use `RIGHT JOIN` with `employee` on the right) so that every department shows up, even ones with zero matching employees.

**A4.**
```sql
SELECT e.first_name, d.dept_name
FROM employee e
LEFT JOIN department d ON e.dept_id = d.dept_id;
```
> `employee` is on the left this time — every employee shows up, and `dept_name` just comes back `NULL` for anyone with a broken `dept_id`.

**A5.**
```sql
SELECT d.dept_name, COUNT(e.emp_id) AS employee_count
FROM department d
LEFT JOIN employee e ON d.dept_id = e.dept_id
GROUP BY d.dept_name;
```
> `LEFT JOIN` here (not `INNER JOIN`) matters — it makes sure departments with 0 employees still show up with a count of `0`, instead of vanishing from the results entirely.

## Solutions — Section B (Medium)

**B1.**
```sql
SELECT d.dept_name
FROM department d
LEFT JOIN employee e ON d.dept_id = e.dept_id
WHERE e.emp_id IS NULL;
```
> The classic "find the gap" pattern: `LEFT JOIN` keeps every department, then `WHERE e.emp_id IS NULL` keeps only the ones where nothing matched on the right side.

**B2.**
```sql
SELECT e.first_name, e.dept_id
FROM employee e
LEFT JOIN department d ON e.dept_id = d.dept_id
WHERE d.dept_id IS NULL;
```
> Same pattern as B1, mirrored — `employee` on the left this time, checking for missing matches on the department side.

**B3.**
```sql
SELECT e.first_name, e.salary, d.manager_name
FROM employee e
JOIN department d ON e.dept_id = d.dept_id
WHERE e.salary > 70000;
```
> A `WHERE` clause on a joined query behaves exactly like it does on a single table — it just filters the combined rows.

**B4.**
```sql
SELECT d.dept_name, AVG(e.salary) AS avg_salary
FROM employee e
JOIN department d ON e.dept_id = d.dept_id
WHERE e.salary IS NOT NULL
GROUP BY d.dept_name
HAVING AVG(e.salary) > 50000;
```
> `WHERE` drops the no-salary rows first, `JOIN` brings in the readable department name, `GROUP BY` buckets by department, `HAVING` filters the buckets. All four files' concepts, one query.

**B5.**
```sql
SELECT d1.dept_name, d2.location
FROM department d1
CROSS JOIN department d2;
```
> With 25 departments, this returns `25 × 25 = 625` rows — every department paired with every location in the table (including its own). No `ON` clause needed, since a `CROSS JOIN` doesn't match anything, it just multiplies.

## Solutions — Section C (Hard / Interview-style)

**C1.**

**Using a JOIN:**
```sql
SELECT e.first_name
FROM employee e
JOIN department d ON e.dept_id = d.dept_id
WHERE d.location = 'Mumbai';
```

**Using a subquery:**
```sql
SELECT first_name
FROM employee
WHERE dept_id IN (
    SELECT dept_id FROM department WHERE location = 'Mumbai'
);
```
> Same result, two philosophies: the `JOIN` version combines the tables first, then filters. The subquery version filters the department table down to a list first, then checks employees against that list. For this particular question — where you don't need to *display* any department columns — either is fine; the `JOIN` becomes the better choice the moment you also want to show `dept_name` in the output.

**C2.**
```sql
-- Original RIGHT JOIN
SELECT e.first_name, d.dept_name
FROM employee e
RIGHT JOIN department d ON e.dept_id = d.dept_id;

-- Equivalent LEFT JOIN
SELECT e.first_name, d.dept_name
FROM department d
LEFT JOIN employee e ON e.dept_id = d.dept_id;
```
> The trick: whichever table needs to keep *all* its rows becomes the **left** table in a `LEFT JOIN`. Since `RIGHT JOIN ... department` meant "keep all departments," swapping to `department` first with `LEFT JOIN` achieves the exact same thing.

**C3.**
```sql
SELECT d.dept_name, AVG(e.salary) AS avg_salary
FROM employee e
JOIN department d ON e.dept_id = d.dept_id
WHERE e.salary IS NOT NULL
GROUP BY d.dept_name
ORDER BY avg_salary DESC
LIMIT 1;
```
> Same shape as B4, but instead of filtering with `HAVING`, we sort every department's average highest-first and grab just the top one. `HAVING` filters groups by a *condition*; `ORDER BY` + `LIMIT` picks the group that *wins*. Different tools, similar territory.

**C4.**
```sql
SELECT d.dept_name, e.first_name AS top_earner
FROM department d
LEFT JOIN employee e ON d.dept_id = e.dept_id
WHERE e.salary = (
    SELECT MAX(e2.salary)
    FROM employee e2
    WHERE e2.dept_id = d.dept_id
)
OR e.emp_id IS NULL;
```
> This one's genuinely tricky — it combines a `LEFT JOIN` (to keep empty departments), a **correlated subquery** (to find each department's own highest salary), and an `OR e.emp_id IS NULL` safety net so departments with literally no employees don't get silently dropped by the subquery condition. This is exactly the kind of layered question that separates "knows JOIN syntax" from "can actually reason through a real business question."

**C5.**
> **One-sentence reason:** there's no `ON` condition and no `JOIN` keyword at all — this old-style comma syntax is a hidden `CROSS JOIN`, silently pairing every employee with every department (100 × 25 = 2,500 rows of mostly nonsense), which is almost never what was intended.

**Fix:**
```sql
SELECT e.first_name, d.dept_name
FROM employee e
JOIN department d ON e.dept_id = d.dept_id;
```
> The comma-style `FROM table1, table2` syntax is a relic from very old SQL — modern SQL always uses explicit `JOIN ... ON` so the matching condition is impossible to accidentally leave out.
