# 9. Single Row Functions

> *"Aggregate functions" from file 3 (`COUNT`, `SUM`, `AVG`...) take many rows and squash them into one answer. Single row functions do the opposite job: they take **one** value and hand back **one** transformed value — one in, one out, every single row, no squashing involved. MySQL has dozens of these. Here are the ones you'll actually reach for.*

---

## 1. What makes a function "single row"?

| | Single Row Function | Aggregate (Multi-Row) Function |
|---|---|---|
| Input | One value per row | Many values across rows |
| Output | One result **per row** | One result **per group** |
| Example | `UPPER(first_name)` | `AVG(salary)` |
| Runs once per | Row | Group (or whole table) |
| Can appear with `GROUP BY`? | Yes, no special rule | Yes — that's the whole point |

```sql
-- Single row: every row gets its own answer
SELECT first_name, UPPER(first_name) AS loud_name FROM employee;
-- 100 input rows → 100 output rows

-- Aggregate: every row collapses into one answer
SELECT AVG(salary) FROM employee;
-- 100 input rows → 1 output row
```

If `COUNT`/`SUM`/`AVG`/`MIN`/`MAX` take a crowd and give you a single verdict, single row functions are more like a mirror — show it one thing, get one reflection back, million times in a row.

## 2. String Functions

### 2.1 `UPPER()` / `LOWER()` — case conversion

```sql
SELECT first_name, UPPER(first_name) AS upper_name, LOWER(first_name) AS lower_name
FROM employee
LIMIT 5;
```

Handy for case-insensitive comparisons too:

```sql
SELECT * FROM employee WHERE LOWER(designation) = 'manager';
-- catches 'Manager', 'MANAGER', 'manager' — all of it
```

### 2.2 `LENGTH()` — character count

```sql
SELECT email, LENGTH(email) AS email_length
FROM employee
ORDER BY email_length DESC
LIMIT 5;
```

> ⚠️ `LENGTH()` counts **bytes**, not characters — for plain ASCII (like these emails) that's the same thing, but for multi-byte text (emojis, non-Latin scripts) use `CHAR_LENGTH()` instead if you want the actual character count.

### 2.3 `CONCAT()` — stitching strings together

```sql
SELECT CONCAT(first_name, ' ', last_name) AS full_name
FROM employee
LIMIT 5;
```

`CONCAT()` happily accepts any number of arguments, mixed types included:

```sql
SELECT CONCAT(first_name, ' is a ', designation, ' earning ₹', salary) AS summary
FROM employee
LIMIT 5;
```

> One free safety feature: in standard MySQL, if *any* argument to `CONCAT()` is `NULL`, the whole result is `NULL` — so a missing `salary` silently nukes an entire summary string. `CONCAT_WS()` (below) fixes this.

### 2.4 `CONCAT_WS()` — concatenate with a separator (and NULL-safe)

```sql
SELECT CONCAT_WS(', ', dept_name, location, manager_name) AS dept_summary
FROM department
LIMIT 5;
```

`WS` = "with separator." Give it the separator once, then as many columns as you like — and unlike plain `CONCAT()`, it just skips any `NULL` arguments instead of returning `NULL` for the whole thing.

### 2.5 `SUBSTRING()` — slicing out part of a string

```sql
SELECT email, SUBSTRING(email, 1, 5) AS first_five_chars
FROM employee
LIMIT 5;
```

`SUBSTRING(string, start_position, length)` — note SQL string positions start at **1**, not 0. Leave off the length to go "from this position to the end":

```sql
SELECT email, SUBSTRING(email, 7) AS rest_of_email FROM employee LIMIT 5;
```

### 2.6 `TRIM()` — removing stray whitespace

```sql
SELECT TRIM('   Delhi   ') AS cleaned;   -- 'Delhi'
```

Real-world messy data loves leading/trailing spaces from copy-pasted spreadsheets. `LTRIM()` and `RTRIM()` trim only one side if you need that precision.

### 2.7 `REPLACE()` — find and swap

```sql
SELECT email, REPLACE(email, '@company.com', '@newdomain.com') AS updated_email
FROM employee
LIMIT 5;
```

### 2.8 `LPAD()` / `RPAD()` — padding to a fixed width

```sql
SELECT emp_id, LPAD(emp_id, 5, '0') AS padded_id
FROM employee
LIMIT 5;
-- emp_id 7 → '00007'
```

Classic use case: generating fixed-width IDs/invoice numbers that sort correctly as text (`'00007'` sorts before `'00042'`; plain `'7'` would sort after `'42'` alphabetically — a trap worth knowing about).

## 3. Numeric Functions

### 3.1 `ROUND()` — rounding to N decimal places

```sql
SELECT salary, ROUND(salary, -3) AS rounded_to_thousand
FROM employee
LIMIT 5;
```

`ROUND(value, decimals)` — positive `decimals` rounds after the decimal point, **negative** rounds to the left of it (tens, hundreds, thousands). `ROUND(salary, 0)` or just `ROUND(salary)` rounds to the nearest whole number.

### 3.2 `CEIL()` / `FLOOR()` — rounding up/down, no half-measures

```sql
SELECT CEIL(43131 / 12) AS rounded_up_monthly, FLOOR(43131 / 12) AS rounded_down_monthly;
```

`CEIL()` always rounds **up** to the next integer, `FLOOR()` always rounds **down** — useful for pagination math (remember `CEIL(total_rows / page_size)` from the Sorting & Limiting file? That `CEIL` is this one).

### 3.3 `ABS()` — absolute value

```sql
SELECT ABS(-42);   -- 42
```

Useful whenever a difference could legitimately go negative but you only care about the size of the gap — e.g. `ABS(salary - avg_salary)` to find who's furthest from average in *either* direction.

### 3.4 `MOD()` — remainder after division

```sql
SELECT emp_id, MOD(emp_id, 2) AS is_odd   -- 0 = even, 1 = odd
FROM employee
LIMIT 5;
```

Same thing as the `%` operator in most programming languages — `MOD(10, 3)` and `10 % 3` both give `1`.

### 3.5 `POWER()` — exponents

```sql
SELECT POWER(2, 10);   -- 1024
```

## 4. Date & Time Functions

These lean on `hire_date` and `start_date`/`end_date` from the dataset.

### 4.1 `NOW()` / `CURDATE()` — the current moment

```sql
SELECT NOW(), CURDATE();
-- NOW()    → 2026-10-10 14:27:03  (date AND time)
-- CURDATE() → 2026-10-10          (date only)
```

### 4.2 `DATEDIFF()` — days between two dates

```sql
SELECT first_name, hire_date, DATEDIFF(CURDATE(), hire_date) AS days_employed
FROM employee
ORDER BY days_employed DESC
LIMIT 5;
```

`DATEDIFF(later_date, earlier_date)` — get the order backwards and you'll just get a negative number, not an error, so double-check which argument goes first.

### 4.3 `DATE_ADD()` / `DATE_SUB()` — shifting a date

```sql
SELECT hire_date, DATE_ADD(hire_date, INTERVAL 1 YEAR) AS first_anniversary
FROM employee
LIMIT 5;

SELECT hire_date, DATE_SUB(hire_date, INTERVAL 90 DAY) AS probation_start
FROM employee
LIMIT 5;
```

`INTERVAL` accepts `DAY`, `WEEK`, `MONTH`, `YEAR`, `HOUR`, `MINUTE`, `SECOND` — mix and match as the problem needs.

### 4.4 `YEAR()` / `MONTH()` / `DAY()` — pulling out a single piece

```sql
SELECT hire_date, YEAR(hire_date) AS hire_year, MONTH(hire_date) AS hire_month
FROM employee
LIMIT 5;
```

Extremely common inside `GROUP BY` — "how many people did we hire each year" is `GROUP BY YEAR(hire_date)`, nothing fancier needed.

### 4.5 `DATE_FORMAT()` — custom date display

```sql
SELECT hire_date, DATE_FORMAT(hire_date, '%d %M %Y') AS pretty_date
FROM employee
LIMIT 5;
-- '25 February 2022'
```

A few format codes worth memorizing: `%d` (day, 2-digit), `%M` (full month name), `%m` (month, 2-digit), `%Y` (4-digit year), `%y` (2-digit year).

## 5. NULL-Handling Functions

You met `COALESCE()` briefly back in the Joins file — here's the fuller picture.

### 5.1 `IFNULL()` — substitute a value when `NULL`

```sql
SELECT first_name, IFNULL(salary, 0) AS salary_or_zero
FROM employee
LIMIT 10;
```

Two arguments only: "if this is `NULL`, use that instead."

### 5.2 `COALESCE()` — same idea, but with a whole fallback chain

```sql
SELECT first_name, COALESCE(salary, 0) AS salary_safe
FROM employee
LIMIT 10;
```

`COALESCE()` takes any number of arguments and returns the **first non-`NULL`** one. `IFNULL(a, b)` is really just `COALESCE(a, b)` with exactly two arguments — reach for `COALESCE()` when you might need more than one fallback:

```sql
SELECT COALESCE(manager_name, 'No Manager Assigned', 'Unknown') AS manager_display
FROM department;
```

### 5.3 `NULLIF()` — the reverse trick

```sql
SELECT NULLIF(salary, 0) AS salary_or_null
FROM employee;
```

`NULLIF(a, b)` returns `NULL` if `a` equals `b`, otherwise returns `a`. Classic use: avoiding a division-by-zero crash.

```sql
-- Without protection, a department with 0 projects would crash this division:
SELECT dept_name, budget / NULLIF(floor_no, 0) AS budget_per_floor
FROM department;
```

## 6. Combining Several Functions in One Query

Functions nest freely — the inside one runs first, same as math class.

```sql
SELECT 
    CONCAT(UPPER(first_name), ' ', UPPER(last_name)) AS full_name_loud,
    designation,
    CONCAT('₹', FORMAT(salary, 0)) AS formatted_salary,
    DATEDIFF(CURDATE(), hire_date) AS days_employed,
    IFNULL(salary, 0) AS safe_salary
FROM employee
WHERE salary IS NOT NULL
ORDER BY days_employed DESC
LIMIT 5;
```

Reading nested functions from the inside out is the trick: `UPPER(first_name)` runs first, *then* `CONCAT()` glues the result together — same logic as `(2 + 3) * 4` evaluating the parentheses before the multiplication.

## Recap

| Category | Functions covered |
|---|---|
| String | `UPPER`, `LOWER`, `LENGTH`, `CONCAT`, `CONCAT_WS`, `SUBSTRING`, `TRIM`, `REPLACE`, `LPAD`/`RPAD` |
| Numeric | `ROUND`, `CEIL`, `FLOOR`, `ABS`, `MOD`, `POWER` |
| Date/Time | `NOW`, `CURDATE`, `DATEDIFF`, `DATE_ADD`, `DATE_SUB`, `YEAR`/`MONTH`/`DAY`, `DATE_FORMAT` |
| NULL-handling | `IFNULL`, `COALESCE`, `NULLIF` |

- Single row functions transform **one value at a time** — one row in, one row out, no collapsing.
- That's the opposite job of aggregate functions (`COUNT`, `SUM`, `AVG`...) from file 3, which take many rows and return one.
- Functions nest — read nested calls from the inside out, same as ordinary math.
- `IFNULL`/`COALESCE`/`NULLIF` are your main NULL-safety net — worth keeping in every query that touches a column that *can* be `NULL` (looking at you, `salary`).
